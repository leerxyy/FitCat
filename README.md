# RITUA 1.0

**Забота в вашем ритме.** Персональный дневник питания, воды, движения и ежедневных ритуалов. Новый продукт на основе задач FitCat 3.25.0, с заново написанными интерфейсом и прикладной логикой.

## Открыть приложение

Размещённая закрытая версия: https://ritua-wellbeing.tinypike66.chatgpt.site

Для запуска из архива нужен Node.js 20 или новее. Зависимости устанавливать не требуется.

```bash
npm start
```

Откройте http://localhost:3000. Не запускайте `index.html` двойным щелчком: модулям JavaScript нужен HTTP-сервер.

```bash
npm test        # автоматические проверки логики и действий интерфейса
npm run build  # готовый статический сайт в dist/
node scripts/serve.mjs --dist  # локальный запуск готовой сборки
```

## Что работает

- Обзор дня: питание и БЖУ, вода, шаги, приёмы пищи и ритуалы.
- Дневник по датам, четыре приёма пищи, произвольные порции и значения с этикетки.
- Планирование будущих приёмов пищи; запланированное не входит в съеденные калории.
- Изменение записей, удаление и возврат через уведомление.
- Вода с быстрыми объёмами, своим объёмом и историей добавлений.
- Ручной ввод шагов и минут активности.
- Собственные ежедневные ритуалы с временем в расписании.
- Минутная дыхательная пауза: шесть циклов, пауза/продолжение, остановка при уходе в фон.
- Статистика за 7 и 30 дней, графики и доступная таблица данных.
- История веса без оценочных категорий; одно измерение на дату.
- 34 встроенных продукта, 6 рецептов, личные продукты, избранное и наборы блюд.
- Поиск в Open Food Facts только по отдельному действию пользователя.
- Профиль с ручными ориентирами; светлая, вечерняя и системная темы, уменьшение движения.
- JSON-резервные копии, импорт RITUA/FitCat, CSV-экспорт статистики.
- PWA-манифест, иконки, кэш оболочки и установка в поддерживаемых браузерах.

## Первое открытие

Без сохранённых данных открывается явно обозначенный пример. Он не записывается в постоянное хранилище. Нажмите «Начать свой день»: создастся личный дневник без демонстрационных записей и измерений.

В профиле можно задать имя и дневные ориентиры. Начальные значения — пример, а не медицинский расчёт. Встроенная пищевая ценность приблизительна; данные конкретного продукта берутся с этикетки.

## Перенос с FitCat

При замене сайта **на том же origin** RITUA считывает известные ключи FitCat и переносит дневник. Исходные ключи не удаляются. Общий домен, протокол и порт должны совпадать; путь сайта на домене этого ограничения не меняет.

Для другого адреса сначала скачайте JSON-копию в FitCat, затем откройте **Настройки → Восстановить RITUA / FitCat** в RITUA. Импорт показывает количество дней и измерений и требует подтверждения замены текущих записей.

FitCat сохранял подробные продукты только для текущего дня. Для прошлых дней RITUA переносит доступные суммарные значения и явно обозначает это в дневнике. Добавленные позже продукты прибавляются к историческим итогам. Полная исходная копия сохраняется в поле `legacy` нового экспорта, включая неиспользуемое оформление и старые данные кошелька.

## Данные и конфиденциальность

Дневник хранится в `localStorage` этого браузера под собственным ключом RITUA. Изменения сначала записываются целиком, затем заменяют состояние интерфейса. Ошибка записи не закрывает форму и не выдаёт сохранение за успешное. Предыдущая корректная версия используется как восстановительная копия.

Очищение данных сайта или приватный режим браузера могут удалить локальные записи. Регулярно скачивайте JSON-копию. Копия импорта ограничена 5 МБ. Данные не зашифрованы отдельным паролем приложения; доступ к открытому браузеру означает доступ к дневнику.

Автоматическая публикация прогресса в Firebase, которая присутствовала в FitCat, удалена. Облачной синхронизации, аккаунтов внутри приложения, оплаты, распознавания еды по фото, фоновых push-уведомлений и интеграций с часами нет. Внешний поиск отправляет только введённый поисковый запрос в Open Food Facts. Размещение закрытого сайта использует вход платформы размещения.

## Размещение

Содержимое `dist/` можно разместить на обычном статическом HTTPS-хостинге, включая GitHub Pages. Сборка поддерживает корень и вложенный путь; ключи кэша отделены по пути. Файл `sw.js` должен отдаваться как JavaScript в корне выбранного пути. Перенаправлять все отсутствующие JS-файлы на `index.html` не нужно.

При смене файлов заново выполните `npm run build`: версия офлайн-кэша вычисляется по содержимому сборки. Обновление активируется по действию пользователя. Если установка или кэширование не поддерживаются, дневник работает в обычной вкладке.

| `app/ui.js` | Диалоги, уведомления, поля и общие компоненты |

| `assets/` | Логотипы, PWA-иконки, фотография |
| `dist/` | Готовые файлы для размещения |
| `tests/` | Тесты расчётов, миграции, действий и офлайн-кэша |

| `docs/VERIFICATION.md` | Проверенное поведение и границы проверки |

## Верификация

Автоматические проверки покрывают основные действия и ошибки хранения. DOM-стенд — тестовый двойник, он не является настоящим браузером и не проверяет отрисовку CSS. Визуальная браузерная проверка и проверка на реальных iOS/Android-устройствах в среде выполнения были недоступны. Подробности — в `docs/VERIFICATION.md`.
